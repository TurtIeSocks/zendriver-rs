1//! Cloudflare Turnstile bypass for `zendriver`.
2//!
3//! See the [Cloudflare chapter](https://turtiesocks.github.io/zendriver-rs/cloudflare.html)
4//! of the [zendriver-rs user guide](https://turtiesocks.github.io/zendriver-rs/)
5//! for end-to-end usage, timeout tuning, and detection-failure diagnostics.
6//!
7//! **Stealth recommended.** Cloudflare Turnstile is somewhat forgiving of
8//! non-stealth Chrome, but `BrowserBuilder::stealth` significantly raises
9//! the clearance success rate.
10//!
11//! Drives the Turnstile checkbox click flow:
12//!
13//! 1. Detect the Turnstile iframe via a shadow-DOM-aware walk of the page's
14//!    main world.
15//! 2. Scroll it into view, re-measure it, and dispatch a raw left-click at
16//!    the 15% × 50% offset inside its box (the default Turnstile checkbox
17//!    location), retrying a swallowed click a few times.
18//! 3. Poll for either the token input gaining a value, or the challenge
19//!    ceasing to be actionable — the clicked iframe no longer a valid click
20//!    target, or every challenge marker gone. See
21//!    [`ClearanceOutcome::ChallengeGone`] for why the first of those is not
22//!    proof the gate was passed.
23//!
24//! **The markers and the click are caller data.** What to look for is
25//! [`TurnstileSelectors`], whether and where to click is a [`ClickPolicy`],
26//! and the click itself can be replaced wholesale via
27//! [`CloudflareBypass::on_click`]. Cloudflare owns all of it and moves it on
28//! their schedule; a caller should be able to follow without waiting on a
29//! release of this crate.
30//!
31//! Two things stay fixed. **What counts as clickable** is the crate's rule,
32//! not the caller's: a widget qualifies only if it has non-zero size and is
33//! not hidden by `visibility` / `display` / `opacity`, and everything below
34//! that bar — including a replacement [`on_click`](CloudflareBypass::on_click)
35//! — is never reached. **How the widget is brought into view** is likewise
36//! fixed, at a centred instant scroll.
37//!
38//! Most users go through `zendriver`'s `Tab::cloudflare()` (feature-gated)
39//! rather than constructing the bypass directly. The
40//! [`CloudflareBypass`] type is the underlying driver.
41//!
42//! ```no_run
43//! # async fn ex(tab: &zendriver_transport::SessionHandle)
44//! #   -> Result<(), zendriver_cloudflare::CloudflareError> {
45//! use std::time::Duration;
46//! use zendriver_cloudflare::{CloudflareBypass, ClearanceOutcome};
47//!
48//! let outcome = CloudflareBypass::new(tab)
49//!     .wait_for_clearance(Duration::from_secs(30))
50//!     .await?;
51//! match outcome {
52//!     ClearanceOutcome::TokenAcquired(token) => println!("got token: {token}"),
53//!     ClearanceOutcome::ChallengeGone => println!("challenge cleared"),
54//!     ClearanceOutcome::TimedOut { saw_challenge } => {
55//!         println!("timed out; saw_challenge = {saw_challenge}")
56//!     }
57//! }
58//! # Ok(()) }
59//! ```
