1//! Frame lifecycle event subscriber — internal.
2//!
3//! Spawned per [`crate::Tab`] at construction time. Subscribes to
4//! `Page.frameAttached`, `Page.frameDetached`, and `Page.frameNavigated`
5//! events on the owning tab's session and maintains the tab's frames
6//! registry (read via [`crate::Tab::frames`]).
7//!
8//! ## Wiring
9//!
10//! Each [`crate::Tab`] owns one background task. At construction time the
11//! task:
12//! 1. Subscribes to the three `Page.frame*` event streams BEFORE awaiting
13//!    `Page.enable` — avoids the race where Chrome fires events between
14//!    the enable reply and our subscription registration.
15//! 2. Fires `Page.enable` once on the tab's session so Chrome starts
16//!    emitting `Page.frame*` events.
17//! 3. Loops over the merged event stream, mutating the registry:
18//!    - `Page.frameAttached` — construct a new [`crate::Frame`] sharing
19//!      the tab's session (same-origin sub-frame; OOPIF frames arrive
20//!      through the [`crate::frame::oopif`] observer path on their own
21//!      child session, NOT this stream), insert it under `frameId`, and
22//!      **spawn** `sweep_dead_provisional_siblings` to evict any dead
23//!      provisional sibling it supersedes. That sweep issues a
24//!      `Page.getFrameTree` round-trip, and it is spawned rather than
25//!      awaited here on purpose — see the note below.
26//!    - `Page.frameNavigated` — update the existing entry's URL in
27//!      place (and backfill the frame `name` the attach event could not
28//!      carry); insert a fresh [`crate::Frame`] if no entry exists.
29//!    - `Page.frameDetached` — remove the entry from the registry.
30//!
31//! ## Nothing in an arm may await a CDP round-trip
32//!
33//! A `tokio::select!` arm is not a background job: while an arm's body is
34//! pending the loop cannot advance, so no other frame event is processed.
35//! That is worse than a delay. The event source underneath is
36//! [`zendriver_transport::Connection::subscribe_raw`], a broadcast channel
37//! carrying *every* raw CDP event, and a subscriber that lags past its
38//! capacity has frames dropped silently. A stalled arm on a busy page
39//! therefore loses `Page.frameDetached` events outright, leaving the
40//! registry reporting frames that no longer exist — with no error anywhere.
41//! Keep the arms to registry mutation; spawn anything that talks to Chrome.
42//!
43//! The task runs until its [`tokio_util::sync::CancellationToken`] fires —
44//! typically when the owning Tab is dropped. Everything it spawns (the
45//! startup `Page.enable`, and each sweep from the attach arm) observes the
46//! same token, so nothing outlives it waiting out a CDP budget.
47

62/// Wait budget for the `Page.getFrameTree` probe that confirms a
63/// same-parent sibling really is a dead provisional frame.
64///
65/// This bound does **not** protect the event loop — the sweep runs in its
66/// own task, which is what protects the loop. It caps how long a wedged
67/// probe keeps that task (and its clone of the registry `Arc`) alive. On
68/// expiry the sweep fails open: nothing is evicted.
69const PROVISIONAL_PROBE_TIMEOUT: Duration = Duration::from_secs(5);

71/// Minimal projection of `Page.frameAttached` — only the fields we need
72/// to construct a [`Frame`]. URL/name are not on this payload; they arrive
73/// on a subsequent `Page.frameNavigated`.

75struct FrameAttachedEvent {

108/// Drive the lifecycle subscriber until `cancel` fires.
109///
110/// `frames` is the [`RwLock`]-protected registry shared with the owning
111/// [`TabInner`]. `tab_weak` is the [`Weak<TabInner>`] handed to each
112/// constructed [`Frame`] so its `tab_for_synthesize` upgrade can return
113/// the owning `Tab`.
114///
115/// Same fire-and-forget posture as
116/// [`crate::network_idle::InFlightTracker::run`] for the `Page.enable`
117/// call: failure is logged + ignored so the subscriber keeps running on a
118/// previously-enabled Page domain.
119pub(crate) async fn run(
120    session: SessionHandle,
121    frames: Arc<RwLock<HashMap<String, Frame>>>,
122    tab_weak: Weak<TabInner>,
123    cancel: CancellationToken,
124) {
125    let mut attached = session.subscribe::<FrameAttachedEvent>("Page.frameAttached");
126    let mut detached = session.subscribe::<FrameDetachedEvent>("Page.frameDetached");
127    let mut navigated = session.subscribe::<FrameNavigatedEvent>("Page.frameNavigated");
128
129    // Fire-and-forget `Page.enable`. Same rationale as
130    // `InFlightTracker::run`: the mock harness never replies to this
131    // call, and in production the subscribe streams above are already
132    // registered, so awaiting the response would only serialize the
133    // first arriving event behind the enable round-trip.
134    //
135    // Cancellation-aware for the same reason the sweep is: an unanswered
136    // call sits on the transport's default budget
137    // ([`zendriver_transport::DEFAULT_CALL_TIMEOUT`], 180s), and nothing
138    // spawned here may outlive the Tab that owns it by that much while
139    // holding a session clone.
140    let enable_session = session.clone();
141    let enable_cancel = cancel.clone();
142    tokio::spawn(async move {
143        tokio::select! {
144            () = enable_cancel.cancelled() => {}
145            res = enable_session.call("Page.enable", serde_json::json!({})) => {
146                if let Err(e) = res {
147                    warn!(error = %e, "frame::lifecycle: Page.enable failed; frame events may be inactive");
148                }
149            }
150        }
151    });
152
153    loop {
154        tokio::select! {
155            () = cancel.cancelled() => {
156                trace!("frame::lifecycle: cancellation received, exiting");
157                return;
158            }
159            Some(ev) = attached.next() => {
160                let frame = Frame::new(
161                    ev.frame_id.clone(),
162                    ev.parent_frame_id.clone(),
163                    String::new(),
164                    None,
165                    session.clone(),
166                    tab_weak.clone(),
167                );
168                frames.write().await.insert(ev.frame_id.clone(), frame);
169                // Chrome occasionally fires `frameAttached` twice for a
170                // single iframe — once with a provisional `frameId` and
171                // again with the committed one — without an intervening
172                // `frameDetached`. Observed on `srcdoc` iframes under
173                // `--headless=new`. Evict those dead entries so the
174                // registry doesn't accumulate frames that
175                // `Page.createIsolatedWorld` would reject with
176                // "No frame for given id found".
177                //
178                // Spawned, never awaited here: distinguishing a dead
179                // provisional from a sibling that simply has not navigated
180                // yet needs a `Page.getFrameTree` round-trip, and awaiting
181                // one in this arm parks every other frame event behind it
182                // (see the module header). Nothing waits on the eviction —
183                // it is pure housekeeping, and a stale row is recoverable.
184                if let Some(parent) = ev.parent_frame_id {
185                    let session = session.clone();
186                    let frames = frames.clone();
187                    let cancel = cancel.clone();
188                    let attached_id = ev.frame_id;
189                    tokio::spawn(async move {
190                        tokio::select! {
191                            () = cancel.cancelled() => {}
192                            () = sweep_dead_provisional_siblings(
193                                &session, &frames, &attached_id, &parent,
194                            ) => {}
195                        }
196                    });
197                }
198            }
199            Some(ev) = navigated.next() => {
200                let frame_id = ev.frame.id;
201                let new_url = ev.frame.url;
202                // `Page.frameAttached` carries no name, so an entry created
203                // from it always starts nameless. Treat a non-empty name on
204                // `frameNavigated` as the authoritative one; never clear a
205                // known name from an event that simply omits the field.
206                let new_name = ev.frame.name.filter(|n| !n.is_empty());
207
208                // Fast path, under a READ guard: refreshing a URL mutates
209                // the `Frame`'s own `RwLock`, not the registry map, so the
210                // ordinary navigation never needs exclusive access to the
211                // registry. Only the rename below replaces a map entry.
212                let needs_rename = {
213                    let map = frames.read().await;
214                    match map.get(&frame_id) {
215                        Some(existing) => {
216                            let name_changed = new_name.is_some()
217                                && new_name.as_deref() != existing.inner.name.as_deref();
218                            // Write through the shared `Arc` on BOTH paths.
219                            // Every `Frame` handle a caller already took
220                            // points at THIS inner, and the rename below
221                            // swaps the registry row for a fresh one those
222                            // handles never see. Writing first means a
223                            // pre-rename handle at least observes the
224                            // navigation that carries the rename.
225                            //
226                            // It does not survive the swap. The NEXT
227                            // `frameNavigated` resolves the new row and
228                            // writes THAT inner, so a handle taken before
229                            // the rename freezes at this URL forever. The
230                            // repair is one navigation deep, not permanent;
231                            // closing it needs interior-mutable
232                            // `FrameInner::name`, which is a public break a
233                            // maintainer has to sign off (see the ignored
234                            // two-navigation test in this module).
235                            *existing.inner.url.write().await = new_url.clone();
236                            if !name_changed {
237                                continue;
238                            }
239                            true
240                        }
241                        // No entry: treat the navigation as the implicit
242                        // attach (Chrome may emit `frameNavigated` for the
243                        // main frame before any subscriber sees an explicit
244                        // `frameAttached`).
245                        None => false,
246                    }
247                };
248
249                let mut map = frames.write().await;
250                if needs_rename {
251                    // Re-look up. The registry is mutated concurrently by
252                    // the spawned provisional sweep and by the OOPIF
253                    // observer, so the row seen under the read guard may be
254                    // gone by now. A name backfill is a refinement, never a
255                    // reason to resurrect a row something else deliberately
256                    // removed.
257                    let Some(existing) = map.get(&frame_id) else { continue };
258                    // `FrameInner::name` is immutable (it backs
259                    // `Frame::name() -> Option<&str>`, which cannot hand out
260                    // a lock guard), so backfilling means replacing the
261                    // registry entry. Everything else is carried over —
262                    // notably the session, which for an OOPIF is a child
263                    // session and NOT this subscriber's.
264                    let renamed = Frame::new(
265                        frame_id.clone(),
266                        existing.inner.parent_frame_id.clone(),
267                        new_url,
268                        new_name,
269                        existing.inner.session.clone(),
270                        tab_weak.clone(),
271                    );
272                    map.insert(frame_id, renamed);
273                } else {
274                    // Re-look up, for the same reason the rename path does.
275                    // The read guard said "no entry", but the OOPIF observer
276                    // and the attach arm both insert into this map, and an
277                    // OOPIF row carries a CHILD session. Inserting blind
278                    // would overwrite one with a `Frame` on the parent
279                    // session, sending every later call on that frame to the
280                    // wrong target — so a row that appeared in the gap is
281                    // refreshed in place instead.
282                    //
283                    // A name on this event is left to the next navigation:
284                    // backfilling it means swapping the row, which is the
285                    // thing being avoided here, and the rename path above
286                    // does it correctly once the row is visible to a read
287                    // guard.
288                    let raced = map.get(&frame_id).map(|f| Arc::clone(&f.inner));
289                    match raced {
290                        Some(inner) => {
291                            drop(map);
292                            *inner.url.write().await = new_url;
293                        }
294                        None => {
295                            let frame = Frame::new(
296                                frame_id.clone(),
297                                ev.frame.parent_id,
298                                new_url,
299                                new_name,
300                                session.clone(),
301                                tab_weak.clone(),
302                            );
303                            map.insert(frame_id, frame);
304                        }
305                    }
306                }
307            }
308            Some(ev) = detached.next() => {
309                frames.write().await.remove(&ev.frame_id);
310            }
311            else => {
312                trace!("frame::lifecycle: all event streams closed, exiting");
313                return;
314            }
315        }
316    }
317}

319/// Evict the registry entries that the freshly-attached `attached_id`
320/// supersedes: same parent, same session, still URL-less — **and confirmed
321/// gone from Chrome's live frame tree**.
322///
323/// The last clause is what separates a dead provisional frame from a
324/// perfectly good sibling that simply has not navigated yet. Both look
325/// identical in the event stream (a second `frameAttached` under one
326/// parent, no `frameNavigated` on the first), so the registry alone cannot
327/// tell them apart; `Page.getFrameTree` can, because Chrome drops a
328/// provisional frame from the tree the moment it commits the real one —
329/// the same reason `Page.createIsolatedWorld` answers "No frame for given
330/// id found" for it.
331///
332/// ## Why the candidate snapshot is taken before the probe
333///
334/// The probe answers a question about one instant, and the answer is only
335/// sound for rows that already existed at that instant. Taking the
336/// candidate snapshot first guarantees the returned tree is at least as
337/// recent as the snapshot, so a candidate missing from it is a frame that
338/// either never made the tree or died before it was taken — both dead.
339/// Collecting candidates *after* the probe would invert that: a frame
340/// attached in the gap would be a candidate that is legitimately absent
341/// from an older tree, and evicting it would drop a live frame. The
342/// re-validation below then re-checks each survivor against the registry
343/// as it stands at eviction time, because the round-trip is a real window
344/// in which rows can be detached, replaced, or navigated.
345///
346/// ## Failing open
347///
348/// Every ambiguity this can see is resolved by keeping the row: no
349/// candidates, a probe error or timeout, a row whose identity changed
350/// under the probe, a row that navigated while it was outstanding. A stale
351/// row in [`crate::Tab::frames`] only costs a lookup that
352/// [`crate::Frame::ensure_isolated_world`] already recovers from, whereas
353/// evicting a live frame loses a handle the caller may still hold.
354///
355/// One ambiguity it cannot see: a frame that is genuinely alive but absent
356/// from *this* session's `Page.getFrameTree` is evicted anyway. That covers
357/// two unverified cases, and neither is helped by the re-validation, since
358/// both look exactly like a dead provisional from here.
359///
360/// The first is a frame Chrome has announced via `Page.frameAttached` but
361/// not yet listed in the tree, if such a window exists. Running the sweep
362/// off the event loop widens that window slightly, because the candidate
363/// snapshot is now taken whenever the spawned task is first polled rather
364/// than synchronously in the arm.
365///
366/// The second is an out-of-process iframe. The session-id filter below
367/// only excludes entries already re-homed onto a child session, so a
368/// parent-side placeholder for an OOPIF would still be swept if Chrome
369/// omits remote children from the parent target's tree. Whether it does is
370/// unverified against a real
371/// browser; if it turns out to, this needs an OOPIF-aware filter or a
372/// grace period before a url-less candidate becomes eligible.
373async fn sweep_dead_provisional_siblings(
374    session: &SessionHandle,
375    frames: &Arc<RwLock<HashMap<String, Frame>>>,
376    attached_id: &str,
377    parent: &str,
378) {
379    // Each candidate is carried as (id, `Arc` identity). The identity is
380    // what lets the re-validation below tell "the row I sampled" from "some
381    // other row that now holds this id".
382    let candidates: Vec<(String, Arc<FrameInner>)> = {
383        let map = frames.read().await;
384        map.iter()
385            .filter_map(|(id, f)| {
386                if id == attached_id {
387                    return None;
388                }
389                if f.inner.parent_frame_id.as_deref() != Some(parent) {
390                    return None;
391                }
392                // OOPIF entries live on their own child session and are
393                // absent from THIS session's frame tree, so the probe below
394                // would read as "gone" for every one of them.
395                if f.inner.session.session_id() != session.session_id() {
396                    return None;
397                }
398                let url_slot = f.inner.url.try_read().ok()?;
399                url_slot
400                    .is_empty()
401                    .then(|| (id.clone(), Arc::clone(&f.inner)))
402            })
403            .collect()
404    };
405    if candidates.is_empty() {
406        return;
407    }
408    let Some(live) = live_frame_ids(session).await else {
409        return;
410    };
411
412    let mut map = frames.write().await;
413    for (id, sampled) in candidates {
414        if live.contains(&id) {
415            continue;
416        }
417        let Some(current) = map.get(&id) else {
418            continue;
419        };
420        // A different `Arc` behind the same id means the row we sampled is
421        // already gone and something re-inserted under its id — a detach
422        // plus re-attach, or the `frameNavigated` rename swap. Evicting now
423        // would delete a frame the probe never asked about. Identity also
424        // subsumes re-checking `parent_frame_id` and `session`, which are
425        // immutable on `FrameInner`.
426        if !Arc::ptr_eq(&current.inner, &sampled) {
427            continue;
428        }
429        // A URL means the frame navigated while the probe was in flight,
430        // and only a live frame navigates. `try_read` rather than `read`:
431        // this runs under the registry write guard, so it must not block on
432        // a slot the navigated arm is writing — and failing open there is
433        // the correct answer anyway.
434        if !current.inner.url.try_read().is_ok_and(|u| u.is_empty()) {
435            continue;
436        }
437        map.remove(&id);
438    }
439}

441/// Every frame id Chrome currently reports under `Page.getFrameTree`, or
442/// `None` if the probe failed or outran [`PROVISIONAL_PROBE_TIMEOUT`].
443async fn live_frame_ids(session: &SessionHandle) -> Option<HashSet<String>> {
444    let tree = match tokio::time::timeout(
445        PROVISIONAL_PROBE_TIMEOUT,
446        session.call("Page.getFrameTree", serde_json::json!({})),
447    )
448    .await
449    {
450        Ok(Ok(tree)) => tree,
451        Ok(Err(e)) => {
452            warn!(error = %e, "frame::lifecycle: Page.getFrameTree failed; keeping possibly-stale sibling frames");
453            return None;
454        }
455        Err(_) => {
456            warn!(
457                "frame::lifecycle: Page.getFrameTree timed out; keeping possibly-stale sibling frames"
458            );
459            return None;
460        }
461    };
462    let mut ids = HashSet::new();
463    crate::frame::tree::walk(&tree["frameTree"], &mut |node| {
464        ids.insert(node.id.to_string());
465    });
466    Some(ids)
467}

483    /// Spawn the subscriber on a mock connection and drain its startup
484    /// `Page.enable`. Once that command has landed the three `Page.frame*`

509    /// One `childFrames` entry for a canned `Page.getFrameTree` reply.
510    fn tree_child(id: &str, parent: &str) -> serde_json::Value {
511        json!({ "frame": { "id": id, "parentId": parent, "url": "" } })

514    /// Poll the registry until `pred` holds, then return a snapshot. Panics
515    /// on timeout rather than asserting on a half-applied event.
516    async fn wait_for(
517        frames: &Registry,
518        pred: impl Fn(&HashMap<String, Frame>) -> bool,
519    ) -> HashMap<String, Frame> {
520        wait_for_within(frames, Duration::from_secs(1), pred).await
521    }
522
523    /// [`wait_for`] with an explicit budget, for assertions where the
524    /// *deadline itself* is the thing under test.
525    async fn wait_for_within(
526        frames: &Registry,
527        budget: Duration,
528        pred: impl Fn(&HashMap<String, Frame>) -> bool,
529    ) -> HashMap<String, Frame> {
530        let deadline = tokio::time::Instant::now() + budget;
531        loop {
532            {
533                let map = frames.read().await;
534                if pred(&map) {
535                    return map.clone();
536                }
537            }
538            assert!(
539                tokio::time::Instant::now() < deadline,
540                "registry never reached the expected state within {budget:?}",
541            );
542            tokio::time::sleep(Duration::from_millis(10)).await;
543        }
544    }
545
546    /// Give a spawned sweep room to finish, for the assertions whose
547    /// expected outcome is that it did nothing.
548    ///
549    /// The sweep runs in its own task, so no registry state proves it has
550    /// run: every row it might evict is already in the map before it is
551    /// spawned, and the row it leaves alone looks the same before and
552    /// after. A negative therefore has no event to wait on. Past the probe
553    /// reply the sweep is one lock acquisition from done, so this window is
554    /// orders of magnitude more than it needs.
555    async fn settle() {
556        tokio::time::sleep(Duration::from_millis(300)).await;
557    }

923    /// A `Frame` is a cheap `Arc` handle and `Tab::frames()` hands out
924    /// clones, so holding one across navigations is the intended usage.

926    /// The name backfill replaces the registry row with a fresh `Frame`, so
927    /// a handle taken in the window between `frameAttached` and the first

933    /// resolve the new row and leave this one frozen — see
934    /// [`a_held_handle_stops_tracking_after_the_rename_swap`], which is the
935    /// same scenario one navigation further along and is `#[ignore]`d

941    /// fn` — a deliberate public break that is a maintainer's call, not

975    /// The write-through's boundary, and the reason it is a stopgap rather
976    /// than a fix: it repairs the navigation that carries the rename and
977    /// nothing after it.
978    ///
979    /// Two navigations, one handle. The first renames the frame and swaps
980    /// the registry row; the second resolves that new row and writes its
981    /// inner. The held handle points at the old one, so it reads `/cart`
982    /// while the registry reads `/checkout` — and
983    /// `loop { if f.url().await.contains("/checkout") { break } }`, the
984    /// obvious way to wait on an iframe, never terminates on that handle.
985    ///
986    /// **Ignored, not deleted.** Passing it requires interior-mutable
987    /// `FrameInner::name` so the backfill mutates the shared inner instead
988    /// of replacing the row, which turns `Frame::name()` into an `async fn`
989    /// and breaks a public signature. That call is reserved for a
990    /// maintainer (founder's review round 1, §5 item 2 — "`Frame::name()`
991    /// and `Frame::id()` interior mutability"). Un-`#[ignore]` this the day
992    /// the break is taken; it is the acceptance test for it.
993    #[tokio::test]
994    #[ignore = "needs interior-mutable FrameInner::name; reserved public API break"]

1001        // Navigation 1 carries the name, so it swaps the registry row.
