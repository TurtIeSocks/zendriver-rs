Chromium binary downloader.

See the Fetcher chapter of the zendriver-rs user guide for cache-layout details and CI integration tips.

Resolves a Distribution + VersionSpec + Platform triple against that distribution’s index, downloads the matching archive, unpacks it into an atomic cache layout, and hands back a path to the executable.

Public entry point is Fetcher; progress is reported through FetcherProgress callbacks tagged with a FetcherPhase.

use zendriver_fetcher::{Fetcher, VersionSpec};

let chrome = Fetcher::new()
    .version(VersionSpec::Latest)
    .ensure_chrome()
    .await?;
println!("Chrome ready at {}", chrome.display());

§Distributions

Distribution::default() is Distribution::ChromeForTesting, so the example above fetches exactly what this crate always has. Two further indexes are available, and only resolution differs between them — download, integrity check, unpack and cache are one shared path:

DistributionIndexKeyed by
ChromeForTestingone JSON manifestversion
UngoogledChromiumthree GitHub repos, one per OSversion (tag prefix)
ChromiumSnapshota GCS bucket per platformrevision
use zendriver_fetcher::{Distribution, Fetcher, VersionSpec};

let chromium = Fetcher::new()
    .distribution(Distribution::UngoogledChromium)
    .version(VersionSpec::Explicit("151.0.7922.71".into()))
    .ensure_chrome()
    .await?;

Availability is a per-platform question — the three ungoogled repos release independently, and the snapshot bucket has no version index at all — so list_builds answers it for the platform you actually want instead of assuming parity.
