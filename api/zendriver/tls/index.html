Process-wide rustls crypto provider.

reqwest 0.12 chose a provider for you as a side effect of the feature name: rustls-tls expanded to __rustls-ring. reqwest 0.13 stopped guessing. Its rustls feature bundles aws-lc-rs, whose -sys C/asm crate breaks musl cross-compilation, so this workspace uses rustls-no-provider and names the provider itself.

Omitting the install is a runtime panic (“no process-level CryptoProvider available”) the first time rustls builds a TLS config, not a compile error, so it must be called before any HTTPS request rather than relied on incidentally.

zendriver-fetcher carries its own copy: it does not depend on this crate, and zendriver depends on it only behind the optional fetcher feature. Both are Once-guarded and the first caller wins, so whichever runs first is correct.
